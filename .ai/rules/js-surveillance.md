# Js Surveillance

## The capture start sequence is ordered on purpose — checklist, camera, countdown, then measure
startNight() runs: window.confirm(PREFLIGHT_MESSAGE) → camera.start() → countdownToLeave() → calibrate → reference upload → detection. The order is load-bearing, do not reshuffle it. The checklist comes before the camera opens because the light must be on before calibration measures the scene and someone who backs out should not have been filmed. The LEAVE_ROOM_SECONDS (5) countdown comes before calibration, the reference photo and the background model, so all three describe an empty room — measuring first would bake the user into the background and record them walking out as a sighting. Copy and timings live in captureLogic.js (PREFLIGHT_MESSAGE, LEAVE_ROOM_SECONDS, countdownMessage). NOTE for tests: the earlier "advanceTimersByTimeAsync(0) settles the start-up chain" advice no longer holds — starting a night now needs advanceTimersByTimeAsync(LEAVE_ROOM_SECONDS * 1000), which the startWatching() helper does; a test that stubs window.confirm false must do so AFTER starting, or the pre-flight cancels the night.

## Large intruders are dropped per frame by changed-pixel total, and the background keeps adapting under them
A person or pet does not arrive as one oversized blob but as dozens of roach-sized fragments, so detector.js gates on the frame total: when the changed-pixel count exceeds maxChangedArea (a whole-frame budget in processing pixels, tuned by hand rather than derived, so read the constant instead of quoting a number) detect() returns [] and sets detector.largeMotion, which capture.js shows as the LARGE_MOTION_MESSAGE status and a red overlay border. Do not freeze the background model during a dropped frame: adaptation is deliberate so a pet that lies down or a chair left in shot is absorbed within seconds and detection resumes around it, instead of the night going blind until it moves. Ghost blobs left where an absorbed intruder stood are stationary and already discarded by the tracker's minDisplacement. Specs pinning this: packages/surveillance/tests/detector.test.js "drops the whole frame…", "keeps absorbing a large thing that stays put…".

## Guest nights: one sink interface, IndexedDB night store, uuid ids, crops as base64
capture.js never branches on who is watching after start-up. buildSink() picks Uploader (logged-in, config.mode absent) or LocalNightSink (guest, config.mode === 'local' from WatchController::watchConfig); both expose storeReference/start/enqueue/flush/end/stop with identical signatures and end() returns {ok, status, reportUrl}. Keep the two in step — capture.test.js mocks both. Local nights live in nightStore.js (IndexedDB 'bugtracker-local'; InMemoryNightStore is both the private-mode fallback (volatile=true) and the test double, contract-tested together via fake-indexeddb). The reference photo is stored as ArrayBuffer+mime; crops stay raw base64 strings on the track record, exactly the ingest shape, so claimNight.js re-sends them untouched. Local ids are uuid strings: report payloads for replay.js use clientTrackId as `id`, and reportControls.trackIdFrom keeps strings so Replay's === highlight works for both server (int) and local (uuid) ids. sessionAnalytics.js is a line-for-line port of ComputeSessionAnalytics with snake_case output keys — its spec mirrors the PHP unit test; change both or neither. The watch report route is generated with WatchController::LOCAL_ID_PLACEHOLDER and localNight.reportUrlFor swaps the real id in.

## The room checklist is the page's own <dialog>, not window.confirm — supersedes the PREFLIGHT_MESSAGE note
CORRECTION to "The capture start sequence is ordered on purpose": the order (checklist → camera → countdown → measure) still holds, but the checklist is no longer window.confirm(PREFLIGHT_MESSAGE). capture-panel.blade.php renders a native <dialog data-capture="preflight"> with data-capture="preflight-start" and "preflight-cancel" buttons, and capture.js askPreflight() calls showModal() and resolves from the dialog's close event: returnValue 'start' means go, anything else (Cancel, Escape) means back out. The copy lives in the Blade, pinned by CapturePageTest, not in captureLogic.js; the library still exports PREFLIGHT_MESSAGE for its own API but the app does not read it. The start button is disabled before the dialog opens and re-enabled on cancel, which is what stops a second (or forwarded start-alias) click calling showModal() on an open dialog, which throws. In capture.test.js, starting a night is: el('start').click(); el('preflight-start').click(); advanceTimersByTimeAsync(LEAVE_ROOM_SECONDS * 1000) — the startWatching() helper does this; backing out is el('preflight-cancel').click() or el('preflight').close(). Do not stub window.confirm for the capture page any more (claim.js, localNights.js and localReport.js still use it for deletes).

## Large motion is dropped silently — no status message, no red border (supersedes the "shows as LARGE_MOTION_MESSAGE status" note)
CORRECTION to "Large intruders are dropped per frame": detector.js still gates on maxChangedArea and sets detector.largeMotion, and capture.js still draws no boxes on such a frame — but it no longer writes LARGE_MOTION_MESSAGE into the status line or strokes a red border on the overlay. The longer status text re-wrapped the capture header's buttons on every frame the message came and went, so the status stays at "Tracking" for the whole night. The library keeps exporting LARGE_MOTION_MESSAGE and watchingState() for its own API; the app does not call watchingState(largeMotion) per frame. Do not bring the per-frame setState back into processFrame.

## A timed night ends from the once-a-second clock, not a setTimeout
The checklist dialog carries data-capture="auto-end" (checkbox) and "auto-end-hours" (number); autoEndAfterMs() in resources/js/surveillance/captureLogic.js turns them into a duration or null (unticked, blank, unreadable or non-positive → null = run until End night). capture.js stores app.autoEndAt = sessionStartTime + duration at night start and updateElapsed() calls endNight() when Date.now() >= autoEndAt. Keep it there: a backgrounded tab clamps and can skip a long setTimeout, but cannot miss a deadline every tick compares against, and a deadline slept through is honoured on the next tick (spec: "a deadline the clock slept through…"). The header shows "Ends HH:MM" via data-capture="auto-end-note"/"auto-end-at" while recording. In specs, do not advance fake timers by hours — the frame loop runs for every tick and times out; use vi.setSystemTime(Date.now() + n * HOUR) then advance 1000ms.

## Every way back to an idle capture page goes through returnToIdle(state)
capture.js has one function for leaving Idle (leaveIdle(): night-help column, "Starting camera…", stage waiting for the camera) and one for coming back (returnToIdle(state): closeCamera(), start button usable with its play icon, setup-help column back, Check camera button back, then the status you pass — 'Idle' for a check closed on purpose, 'Error' or 'Too dark' for a start the page gave up on). The start and check catch handlers, the check toggle-off, and the too-dark path all call it; do not add a fifth path that hand-picks a subset — that is how a failed reference upload came to leave the camera streaming behind the sample room. closeCamera() is unconditional and null-safe, but the pre-start close is guarded on app.previewing so the camera-stop stub counts stay honest in specs. The elapsed clock interval is app.clockTimer and endNight() clears it alongside loopTimer.

## The nights list pages client-side, five a page, with the paging decision in localNightsLogic.js
"Nights on this device" is filled by localNights.js from the IndexedDB night store and paged in the browser: paginate(items, page, NIGHTS_PER_PAGE=5) and pageSummary() live in resources/js/surveillance/localNightsLogic.js (pure, node-env spec localNightsLogic.test.js), the same split as captureLogic.js/claimLogic.js. The current page is kept across renders and paginate() clamps it, so removing the last night on the last page falls back to the page before. Markup hooks in watch-panel: data-nights="pager" (hidden while one page holds everything), "page-summary", "prev", "next" — the DOM spec fixture in localNights.test.js needs all four. Flux's pagination component is for Laravel paginators and is not used here.

## The dashboard import panel is one row a night, each with its own room and customer; claim.js re-renders without losing what was typed
dashboard.blade.php #claim-nights is a per-night list (data-claim="rows" filled from data-claim="row-template"; cells: name, started, sightings, status, controls{customer select, room input, import}, saved{remove}). The user's customers come in the panel's data-config as `customers: [{id,name}]` (own customers only; the select is hidden when the list is empty). claim.js imports ONE night per click via claimNight(store, id, {room, customerId}) — customer_id is validated server-side with Rule::exists scoped to the user (importNightRules(User $user)). render() snapshots each row's typed room/customer by night id before rebuilding rows and reapplies them, so importing one night does not wipe the others' choices; keep that when touching render(). After a successful import it dispatches the Livewire event 'night-imported', which ⚡sessions listens for (#[On]) to re-render — no page reload. The list is capped at max-h-80 with overflow-y-auto. The panel is hidden while the store holds no nights at all; saved nights still show (with Remove local copy) so their copies can be cleared. DOM spec: tests/js/surveillance/claim.test.js.

## claimNight() deletes the local copy once the account has the night — only the local report page keeps it
claimNight(store, id, {…, keepLocalCopy = false}) calls store.deleteNight() after a successful import, so the dashboard panel and the watch-page list drop the row on import. Only localReport.js passes keepLocalCopy: true, because that page IS the copy and stays readable with a link to the account report (the night is patched with claimedSessionId instead). Consequently a "saved to account" row in either list is one claimed from its report page. Do not re-add a "mark claimed" step to the list flows, and do not delete from localReport.js's claim. Mocks of claimNight in claim.test.js / localNights.test.js must deleteNight to match.
